Minimal Chromium Rewrite Execution Plan

25 August 2026 · Author: Puvaan · Context: PuvaanRaaj/mini-browser 2.x

The objective is a standalone Chromium browser that wins measured workloads without weakening Chromium's sandbox, site isolation, compatibility, or secret storage. “Fastest” remains a release target until repeatable competitor measurements prove it.

Architecture decision

Minimal 2.x will fork the complete unbranded Chromium browser at a pinned stable revision. Electron 1.x remains installable until profile migration, Google website sign-in, passkeys, password storage, TOTP, updates, and Windows packaging all pass release gates. The Chromium checkout remains out of tree; this repository owns a small manifest, build arguments, patches, product resources, benchmarks, and migration tooling.

Performance contract

Every release measures cold and warm startup, first navigation, ten-tab load, resident memory, idle CPU, and controlled energy impact. Measurements use clean profiles, local deterministic pages, two warmups, and seven measured runs on the same machine and power state. A security or compatibility regression cannot be traded for a benchmark win.

The first Electron reference run on this Mac recorded 407.45 ms cold app-ready, 128.07 ms warm app-ready, approximately 1.15 GiB for ten tabs, and 0.58–1.04% sampled idle CPU. The existing market harness produced Chrome and Firefox data with a different startup boundary; those numbers must not be presented as direct wins until Minimal Chromium uses that identical external-browser harness.

Each candidate starts as trace replay or an experiment behind a feature flag. It ships only when it beats Chromium's existing Performance Manager at p50 and does not damage p95 latency, reload rate, correctness, or energy use.
