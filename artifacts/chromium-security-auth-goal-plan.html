Minimal Chromium Security, Authentication, and Performance Goal Plan

24 August 2026 · Author: Puvaan · Repository: PuvaanRaaj/mini-browser

Decision: shelf the native Rust rewrite for now. PR #4 remains a draft and its branch is preserved as a future migration/reference point. The active product is the existing Electron/Chromium app.

Outcome

Make the current Chromium app fast enough to feel immediate, secure enough for daily browsing, and capable of Google sign-in, passkeys, and a local password manager without storing secrets in the renderer.

The target is staged delivery with measurable gates. “Fast” never permits disabling Chromium security, sandboxing, certificate checks, or origin isolation.

Non-negotiable security rules

  • Never store password, TOTP, OAuth refresh, or passkey secrets in localStorage, renderer memory longer than needed, URLs, logs, or telemetry.
  • Never expose a general-purpose IPC channel, Node API, filesystem API, or shell API to remote pages.
  • Do not silently make the browser persistent. The user chooses private or persistent profile mode, with a clear reset/delete action.
  • Do not use a fake user agent as the authentication strategy. Google policy can change; system-browser OAuth is the reliable app-login path.
  • If safeStorage reports an unprotected backend, refuse to create or unlock the vault rather than silently storing plaintext.
  • Use OS credential providers for passkeys; do not implement a home-grown WebAuthn or password-encryption scheme.

First implementation slice

  1. Keep PR #4 draft and create the Chromium hardening branch from the current Electron worktree without discarding its uncommitted fixes.
  2. Add sender validation and sandbox/security regression tests before adding any credential API.
  3. Move TOTP persistence behind a main-process vault interface, with an explicit migration from the existing renderer storage.
  4. Add the profile-mode model and only then implement Google OAuth and passkey persistence.
  5. Run the benchmark suite and browser acceptance matrix for every subsequent PR.
